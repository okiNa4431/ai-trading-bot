# Phase 11：証券別品質・隔離と合成データ専用MVP

## 実装範囲

今回の仮想売買は **SYNTHETIC ONLY**。実Alpacaデータへの接続・承認ではない。
既存の読取Workflow、厳格診断、証券登録簿、Gemini、Supabase schema、Paper/live設定、cronは変更しない。
実市場の4不連続の原因は未確定のまま。残る96証券をELIGIBLEと認定したものでもない。

`security_quality.py` はI/Oを持たない証券別評価関数。既存TickerAssignment・SecurityRegistryの期間／イベント検証を再利用する。
既存の100証券101別名はQualityUniverse.from_catalogで参照できるが、実取得Workflowへの接続は追加しない。
未確認の複数別名を結合せず、同一性・期間が矛盾する対応はバッチ停止する。rawの改名・価格調整はしない。

## 品質・レビュー・利用権限を分離

各security_idについて、次の独立フィールドと理由・判定時刻・証拠観測時刻を保持する。

| 軸 | 状態・意味 |
|---|---|
| data_quality_status | PASSED / FAILED / UNKNOWN：要求窓のデータ検査 |
| identity_review_status | PASSED / UNKNOWN：対象期間を覆う証券同一性レビュー |
| corporate_action_status | PASSED / UNKNOWN / UNSUPPORTED：企業行動レビューと未対応イベント |
| data_usage_permission | UNKNOWN / PRIVATE_READ_ONLY / SYNTHETIC_ONLY：用途別許可 |
| strategy_eligibility | ELIGIBLE / QUARANTINED / UNKNOWN：上記を全て考慮した結論 |

ELIGIBLEには正常な価格だけでなく、十分な履歴、利用可能だったレビュー、範囲を覆う根拠、用途許可が必要。
今回SYNTHETIC_ONLYだけを売買可能にする。市場データはレビューが全て揃ったように見えても、この実装からELIGIBLEへ昇格できない。
ReviewFactの観測日時より前にはレビューを使用しない。市場レビューが観測日より未来の期間まで確認したという主張も採用しない。
合成生成器の既知の契約だけは、synthetic://根拠とsynthetic originの両方があるときに全生成期間の条件を宣言できる。実市場への流用は禁止。

## バッチ停止と証券別隔離

バッチ全体の停止：未完ページ、応答条件・feed・adjustment・calendar不一致、未確定／未来バー、未知の別名、証券・別名の衝突、rawの出所・メタデータ不一致、帰属できない不正行など。
HTTP認証・要求上限・承認ゲート等は既存読取経路で停止し、その制限を変更しない。新モジュール自身はHTTPを行わない。
証券別隔離：帰属を確認できた銘柄の欠損、重複、不正OHLCV、35%超不連続、期間外観測、既知の未対応企業行動。
証拠・レビュー・許可・履歴不足はUNKNOWN。出来高0だけでは隔離しないが、既存PaperBrokerは出来高0のバーでは約定しない。
欠損補完、異常行の黙った破棄、銘柄削除はしない。正規化段階で誰の異常か分からなくなった場合は個別隔離へ格下げせず、バッチ停止する。

QualityAssessmentに全母集団の証券状態を保持し、summaryでは件数・理由を集計する。
市場用の公開レポート変換は既存ReadOnlyQualityReport（purpose=diagnostic_only / strategy_approved=false）のみ。価格・ティッカー別履歴は含まない。
MVPのbatch_statusとstrategy側statusを別に記録する。例えば、検査できたバッチが正常でも、隔離済み保有銘柄があれば売買はSAFE_STOPになる。

## 先読み・選択バイアス

QualityHistoryは時刻を前進させて全証券の状態を追記する。母集団の変更、過去へ戻る判定を拒否する。
一度隔離した証券は、問題が窓から外れたという理由だけで自動復帰しない。今回解除操作は実装しない。
後日判明した企業行動は観測時刻と効力時刻の両方を満たしてから隔離し、過去のスナップショットを書き換えない。
保有銘柄を隔離した場合、既知でない価格を捏造して清算・評価しない。停止後の現在資産・累積リターン・比較リターンはnullとし、最終有効評価日時と処理済み約定は残す。
未保有の隔離銘柄のPENDINGはキャンセルできるが、保有銘柄の自動強制売却はしない。

母集団・理由・時刻別状態と日次資産曲線を内部結果に残すため、将来の除外影響測定に使用できる。
現在の実銘柄一覧を歴史時点の投資可能ユニバースとは扱わない。今回の母集団は生成された100個のSxxxx銘柄であり、実在100証券とは別。

## 合成MVPの動作

`config/synthetic-mvp.yaml` は既存config/swing.yamlとは独立した仮設定。
既存SwingData.synthetic、PaperBroker、SQLite ledger、OrderPlannerのestimate、known_marks、metricsを再利用する。
既存スイング戦略の201日ウォームアップ／ATR条件は上書きしない。

- 100合成銘柄・221 NYSE営業日、seed=551。最初の60営業日は準備、161営業日を評価。
- SMA20 > SMA60かつ直前20営業日の高値更新でエントリー。
- 終値で8%損切り、エントリー以降の既知の終値／取得始値ピークから12%下落で退出。
- 最大保有30営業日：取得日を1日目とし30日目の終値で退出注文、次の適格始値で約定。欠損時に架空の約定はしない。
- 目標1銘柄9%、最大8保有。既存の1銘柄10%・株式80%・現金20%の約定後リスク制限を維持。
- 手数料USD1／注文、スリッページ0.1%、既存FXコスト0.25%。JPY100万円のうち80万円を明示的に合成USD/JPYで交換する。

注文は終値後に登録し、別営業日の確定バーを取得できてから、その始値で歴史約定を記録する。
約定に用いる品質承認は当日始値時点で凍結する。当日終値で判明した異常を、その朝の約定取消へ遡及適用しない。
同じ日の終値判断を同じ日の始値で約定する呼び出しは拒否する。後続バーなしはPENDING。約定は既存order_idで冪等。
価格上昇等による保有比率の変化は評価違反として記録し、新規買いを止める。市場変動後も常に比率が上限以下と保証するものではない。
損切り・トレーリングは日次終値のシグナルで、次の始値までのギャップ損失を8%等に限定する注文ではない。

判定例として、合成契約上97証券をELIGIBLE、1証券を未対応企業行動で隔離、2証券を同一性／企業行動レビュー不足でUNKNOWNにする。
これらのfixtureは生成時点で宣言された模擬レビューであり、実市場の確認実績ではない。

## ベンチマーク・出力

ベンチマークは、除外銘柄も含む全100合成銘柄の等株数価格指数を初日に80%購入し、JPY現金20%を保有するモデル。初期FX・売買摩擦を考慮する。
ベンチマークは初期80/20のbuy-and-holdで、日々20%現金へリバランスはしない。戦略とのリスク配分は完全同一ではない。
実オルカンNAV・ETF価格は取得せず、この比較をオルカン実績と表示しない。実NAVの既存公開制限は維持する。
最大ドローダウンは日次評価からの値。日中の最大ドローダウンとは主張しない。短い期間の年率リターンは算出しない。
勝率は約定済みSELLの実現損益が正である割合。trade_countは約定数、risk_exit_countsは登録した注文シグナルの理由であり、約定数と混同しない。

出力はsyntheticを明示した集計JSON。初期資金、評価額・リターン・最大ドローダウン・現金比率・保有数・約定数・勝率・比較差分・品質件数を含む。
一時SQLiteの注文・約定・現金・株数・平均取得原価は既存ledgerで整合管理し、終了後にDBを削除する。既存口座の再利用・リセットは拒否する。
入口は合成生成器の出所表示とSxxxx母集団も確認し、licensed指定・Alpaca出所・実銘柄名の混入を拒否する。保留BUYの見積費用を予約し、未約定SELLの予定代金は新規買いへ使わない。
既存レポートのmetricsと同じ集計方式を使い、Web／Pages／Supabaseへ反映しない。
実行した標準設定の集計は `docs/phase11-synthetic-result.json`。これは **合成データの動作検証** であり利益実績ではない。

## 手動実行

リポジトリ直下で次を実行する。APIキー不要。Alpaca、Gemini、Supabase、証券注文APIを呼ばず、cronもない。

```powershell
uv run python scripts/synthetic_mvp.py
```

COMPLETEなら終了コード0、SAFE_STOPなら1。実行ごとに新規の一時口座を生成する。
既存の実市場読取Workflowとは独立し、新しい実市場通信ゲートは追加していない。

## 残る確認

実データ投入には、用途別契約、証券同一性・履歴、時点別ユニバース、企業行動のraw適用・調整・配分、為替鮮度、保有中隔離時の運用、監視・復旧を別途レビューし明示承認する必要がある。
過去レビュー情報のない期間はUNKNOWNである。今回、品質レポートから市場データを売買へ渡す許可型は設けていない。
実Alpaca、Gemini、市場データの保存、実証券注文、定期実行の開始は行わない。
