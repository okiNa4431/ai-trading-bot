# Phase 4 実オルカンNAV追加検証（2026-10-17 JST）

## 結論と範囲

公式の設定来CSVを通常のHTTP GETで取得し、実データの取込・保存・再取込・100万円の口数/評価額/リターン計算を非公開ローカルで実行した。対象は運用会社コード253425、協会コード0331418A、ISIN JP90C000H1T1。ETFやMSCI指数、合成価格を実NAVの代わりに使っていない。

継続自動取得・Supabaseへの実NAV転送・公衆公開の包括的な利用許諾は未確認であり、有効化していない。実NAV、価格から算出した比較数値、ダウンロード原本、実行JSONはGit対象外の `data/benchmark/research/` のみに保存した。本報告に実NAVや価格由来の計算結果は転載しない。これは一般的なライセンス取得を意味しない。

既存の継続口座の開始時刻は変更していない。今回Supabase・Geminiの実APIへ接続せず、口座・判断履歴・使用量の削除/リセット操作は0。Phase 5の定期売買は開始していない。

## 申込受付日と適用基準価額日

公式ページにリンクされた[2026-07-25版の交付目論見書](https://www.am.mufg.jp/pdf/koumokuromi/253425/253425_20260725.pdf)のお申込みメモを確認した。購入価額は受付日の翌営業日の基準価額、原則締切15:30、販売会社によって異なる。NY・ロンドン・香港の取引所/銀行の休業日は申込不可。

公式ページ「お申込み不可日」の公開表示が参照するカレンダーを通常アクセスで調査した（`/mukamapi/holiday_calendar_list/?fund_cd=253425&site_type=1`、基準日2026-10-16）。10〜12月の対象ファンドを確認し、10月1日と19日は香港休業で申込不可だった。このエンドポイントを定期取得処理として組み込んではいない。

継続口座は2026-10-16 23:36:07 JST開始で締切後、17〜18日は週末、19日も申込不可。原則ルールでは20日受付・21日NAVが最初の候補になる。販売会社固有の条件や停止があれば再確認が必要。21日の実NAVが未公表の現在、16日NAVで遡及購入したことにしない。継続口座との実績比較はまだ開始できない。

`ApplicationCalendar` は範囲・公式出所・確認時刻・海外/販売会社休業日・短縮日・販売会社締切を記録する。最初の受付可能日、翌国内営業日の適用日、範囲不足を検証する。原則15:30の当該時刻以降、短縮日の11:30以降は翌受付可能日となる。実CSVの購入初期化には明示的なレビュー済みカレンダーを要求する。

## 実値で実行した比較

10月5日09:00 JSTを仮の開始日時、同日を受付日、6日を適用NAV日、16日を評価日とする、別枠の回顧的な算術検証を実行した。公式カレンダーで5日の申込不可はなく、6日が翌国内営業日であることを確認した。

双方100万円で、整数口数 `floor(初期資金 × 10000 / 購入NAV)`、端数は現金、評価額 `口数 × 評価NAV / 10000 + 端数`、リターン `評価額 / 初期資金 - 1` をDecimalで計算した。比較相手は現金保有シナリオであり、AI Botがこの期間に運用した成績とは表示しない。購入手数料0、税引前、追加投資/売却なし。期間内の全国内営業日のデータが存在し、分配金0であることも検証した。

実値を含む結果は所有者向けの `data/benchmark/research/actual-comparison-private.json`、原本は同ディレクトリの `253425.csv`。過去時点でこのファイルを取得していたと偽らず、観測時刻は現在のまま。継続口座のスナップショットへ書き込まない。

## 発見・修正した問題

1. **取引所と投信の営業日混同**：JPXカレンダーが2020-10-01を売買停止日として除外し、実在する投信NAVを拒否していた。[JPXの公式発表](https://www.jpx.co.jp/news/1030/20201001-04.html)と公式CSVを照合し、この取引障害を国内金融営業日の休業扱いから除外した。祝日・即位関連休業日を除外する検証は維持した。全原本と合成境界テストで再検証した。
2. **締切後/海外休業日の適用日誤認**：国内翌営業日だけでは正しくない。原則締切、短縮日、レビュー済み海外/販売会社休業日を考慮する検証と、受付日/適用日/根拠の保存を追加した。
3. **公表時刻不明と再取得の扱い**：観測境界方式を明示し、原本ハッシュが更新されても同じ過去NAVの初回観測を保持する。価格訂正は監査付き処理がないため拒否し、ファイル全体の検証失敗時は取込を行わない。
4. **購入NAVの可用時刻の先読み**：購入初期化時刻と購入NAVの公表/取得境界より前の時刻に、後から購入情報を使って評価することを拒否した。回顧検算は独立経路とし、運用スナップショットの時刻条件を緩めない。
5. **派生公開に購入価格の権利が必要**：最新NAVだけが公開許可済みでも、無許可の購入NAVを使った口数/比較値を公表できてしまう問題を修正。購入・評価の両NAVの許可を要求し、旧レコードの新しい許可フィールドはfalseとして扱う。全比較額・リターン・超過損益を非表示にする回帰テストを追加した。

## 残存条件

自動継続取得・クラウド保存・価格/派生比較値の公開は、提供元の許諾を別途確認するまで有効化しない。内部ローカルCSV方式による初回の実NAV計算検証は完了したが、継続口座との実績比較は未来の適用NAV待ち。これはソフトウェア側でデータを捏造して解消できる事項ではない。分配金の台帳処理・監査付きNAV訂正は従来どおり停止条件とし、Phase 5の機能は追加しない。Google APIの503に対する再試行も追加実行も行っていない。
