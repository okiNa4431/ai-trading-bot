## スクリーニングと情報時点

各時点で公表・取得済みの日足だけを使用し、201営業日の履歴でSMA200とリターンを計算する。RSI/ATRはその窓の14本で初期化しWilder平滑化する。先の価格・将来の不正データ・未公表イベントをランキングや除外理由へ混入させない。最新日足が不正な銘柄を有利に除外して残りを買うことを避け、全体の新規買付を凍結する。

Stage 1は50程度、Stage 2は設定10〜20（既定15）、同一セクター既定3候補。保有・PENDING対象はランキングと別枠で必ず追加し、20を超えても管理対象から落とさない。新規エントリーはcommonのみ。ETF・ADR・preferred・special、低位・低流動性・過大変動・出来高0は理由付きで除外する。保有銘柄の出来高0はスキーマ上の不正値とはせず、取引停止等の確認が必要な運用停止理由とする。

銘柄のlisted/delisted、metadata_atを使い、上場前・メタデータ判明前・上場廃止後を新規候補にしない。現在の銘柄リストだけから、実市場の過去ユニバースを復元済みとは扱わない。point-in-timeの根拠がないデータは生存者バイアスを明示する。新モジュールの価格生成・約定入力はUS合成データに限定し、未審査の実価格へ合成時間足や合成FXを当てない。

5〜20営業日はソフトな目安。ルール戦略は保有日数とトレンド悪化を併用し、リスク低下・トレンド崩れでは5日未満でも退出し、20日経過だけでは売却しない。学習・最適化を行ったという意味のtrainingではなく、今回は201営業日の指標ウォームアップを未使用評価期間から分離した。walk-forwardの分割窓は実装・試験したが、実市場での複数fold実証やパラメータ最適化は実施していない。

## A・B・Cと約定の定義

- A：引け後に1回判断。日足だけの入力も動作し、次営業日の始値を次の確定バー取得後に認識する。
- B：日次選定＋保有・PENDING・独立した市場proxyの監視。急落、ATR変動、変動率上昇、比率逸脱、PENDINGリスクを検出し、hold／sell／freezeを切替可能。freezeは将来のPENDING BUYも取消す。過去の約定を巻き戻さない。
- C：セッション9:30起点の完全な時間足で通常6回、短縮日は3回。最後の30分を1時間足と偽らない。日次選定は同じ確定日足から更新する。

B/Cは新鮮で利用権のある時間足がなければUNAVAILABLE_INTRADAY。Aの入力を繰り返して日中監視成功としない。A/B/Cの比較では、判断頻度以外の合成系列、既存約定エンジン、手数料、spread、slippage、FX費用を共通にした。

注文受付では残高・約定を変更しない。requested_atより後に始まり、確定・取得済みになったバーだけが約定候補。次の適格バーがなければPENDING。合成時間足の最後の部分足は、既存仕様に合わせ名目1時間の終了まで待つ。そのため日次評価は最終部分足の確認後にも更新し、遅く判明した約定コストを成績から落とさない。

SELL STOPは受付後に始まったバーのlowが閾値に達したときだけ約定候補になる。ギャップではmin(open, stop)を参照し、さらに売却slippage・半spread・手数料を差し引く。バー内でのみ発動した場合、実際の秒単位発動時刻は不明なので、過去モードの記録時刻を確認時点に置く。tick単位の再現、気配数量・部分約定・価格衝撃は今回のモデル範囲外。

Windowsローカル、各221営業日、日次スクリーニングの実測。時間はtracemalloc有効下で、OS RSSや実Supabaseの測定ではない。

Parquetは実際にメモリ上で圧縮して計測したが、symbol/timestamp・索引・バックアップ等は除外した下限的な大きさである。全14比較ケースの隔離SQLiteは合計31,739,904 bytes。実Supabaseの使用量・転送量とは別。実API要求数は0。

[Supabase公式Free](https://supabase.com/pricing)はDB500MB・Storage1GB・egress5GBを掲げる。処理のメモリ規模自体は小さいが、現在の本番使用量・既存履歴・raw JSON・世代複製・索引を足した容量を測定しておらず、無料枠で長期運用可能とは断定しない。17.6MB級の原本全体を毎回DBの不変世代へコピーする既存方式に、そのまま2,000銘柄を接続しない。私的オブジェクト保管・差分マニフェスト・保持上限等の設計と許諾が別途必要。

再現コマンド（新しい出力先を指定する。既存先は上書きしない）：

```text
uv run python scripts/swing_research.py --output data/swing-new-run
```

`report.json`は全指標・政策差・時刻・停止理由、`report.md`は日本語の概略を出力する。CLIは資格情報を読まず、接続先や口座名を指定する入力を持たない。

## Alpaca Basicの日次2,000銘柄評価

新しい提供元を無制限に増やさず、Alpacaと既存の[公開規約調査](us-data-public-terms-review.md)を再利用した。公式の[Historical bars](https://docs.alpaca.markets/us/reference/stockbars)は複数symbols、1Day、raw、feed=iex、最大10,000 **総行数/ページ**、next_page_tokenを提供する。銘柄順のため最初のページに一部銘柄しかなくても、ページングを終えるまで欠損と判定しない。asofは名称対応用で、過去ユニバース全体の構成証明ではない。

100銘柄ずつに分ける試算では、2,000×221日=442,000行の初期取得は最少60ページ、2日重複の差分は20要求/営業日が下限。実際にはページが少ない場合もあり、追加ページ・再取得・企業行動・銘柄情報・FXを別計上する。[Basic仕様](https://docs.alpaca.markets/us/docs/about-market-data-api)の200要求/分に対して技術的には候補だが、未取得なので実際の要求数・被覆率・遅延は未検証。feed省略のSIPを意図せず使わない。IEXの出来高を全市場出来高として扱わず、実市場で2,000普通株が流動性条件に通る保証もしない。

| 条件 | 確認状況 |
| --- | --- |
| 日本在住個人 | [世界中からPaper Only登録可能](https://docs.alpaca.markets/us/docs/paper-trading)。登録時の適用標準契約は別確認。個別メールを一律必須にしない |

| 派生特徴量・無料Gemini | 公式MCPのAI利用案内あり。ただし無料Gemini側の製品改善・学習を含む今回の権利は未確定 |

Twelve Basicは既存調査の800 credits/日に対し、全2,000銘柄の日足を各1 creditで毎日取得すると枠を超えるため、第一候補から外した。USD/JPYは既存候補の利用権・鮮度確認が別に必要。日次参照FXを取引用の新鮮なレートへ偽装しない。

## 安全性・DB影響

- 実データ・実Gemini通信0回。市場取得停止ゲート、API上限8/日・200/月、再試行0、既存共有予約を維持。
- ローカルSQLiteは**明示的なオフライン研究用**で、Supabase障害時のfallbackではない。研究は新規test-swing-*のみ、既存先への再送・上書きは拒否。
- RUNNING判断は戦略呼出し前に記録。タイムアウト等は安全停止し、不明結果を成功・失敗として再送しない。
- 分割・配当・上場廃止等は観測可能になった時点以降に停止。未来イベントでは停止しない。価格欠損、必要な時間足欠落、FX異常も停止する。
- STOP・spread等は既存JSONレコードの追加フィールド。旧レコードは既定値で復元。SQL・テーブル・RLS・RPCの変更、所有者migration、実Supabase適用は**なし**。新形式を保存した試験口座を旧バージョンで読む場合の互換性は保証しない。
- 実PostgreSQLの隔離試験で、新契約の再読込と期限切れfencingの拒否を確認する。既存の排他・応答喪失・復旧試験も回帰する。
- paper-live、既存fixture／実相場隔離口座、注文・API履歴は操作していない。Webや公開projectionのコードも変更していない。

## 最終判断と残る条件

**推奨頻度はAを基準とする。定期運用開始不可。** 合成試験ではCやB-sellのDD改善もあるが、短い構成済み相場、追加API・コスト、未確認のデータ権・品質を考慮し、実運用方式の優劣を確定しない。

実市場の次段階は、(1)Alpaca等の適用標準契約と保持・外部AI権、(2)普通株ユニバースのpoint-in-time根拠、(3)日足・FX・企業行動の実品質、(4)2,000銘柄の私的保管と実容量・転送測定、(5)手動・新規隔離口座、(6)十分な未使用期間・相場局面・walk-forward比較、(7)オルカン適用NAVと公開権、の順に確認する。個別メールなしで解決できる標準契約・公式資料を優先する。
